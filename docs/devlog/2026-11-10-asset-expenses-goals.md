# 2026-11-10 자산·지출 장부와 목표 관리

기존 `/income` 경로의 `수입 추이`를 `자산·지출` 영역으로 확장하고 현황·지출·목표 탭을 추가했습니다. 사냥과 보스의 기존 경로·저장 계약은 건드리지 않았습니다.

## 구현

- 선택한 비밀번호 기록장 단위로 시작 잔액/기준 시각, 수동 지출, 실제 잔액 조정, 목표, 판매 완료 영수증을 별도 JSON 필드에 저장합니다. 기존 사냥 `records`와 보스 `boss_plans`는 변경하지 않습니다.
- 자산 데이터에는 별도 낙관적 revision을 두어 동시 기기 저장 충돌을 409로 거부합니다. SQL 마이그레이션은 기존 사용자 기록을 변환하거나 삭제하지 않고 자산 기본값과 revision 컬럼만 추가합니다.
- 시작 잔액이 없으면 0으로 추정하지 않고 입력을 안내합니다. 기준일 이전 기록은 합산하지 않으며 날짜 단위 사냥·보스·지출 기록이 기준일과 겹칠 때 포함 선택을 요청합니다. 시작 잔액은 입력한 게임 잔액과 KST 기준 시각으로 저장합니다.
- 잔액 계산은 시작 잔액 + 기준 이후 사냥 메소 전후 차액 + 클리어 보스 결정석 + 판매 확인 완료된 본인 실수령액 - 사냥 차액에 이미 포함되지 않은 지출 + 명시적 조정 차액입니다. 조정은 기록으로 보관하며 수입·지출에 분류하지 않습니다.
- 새로 만든 과거 물욕템 기록을 자동 판매 처리하지 않고 판매 확인 대상으로 표시합니다. 예상 본인 몫은 참고값으로만 보이며 판매 완료 액수만 잔액에 더합니다. 기존 보스 수익 화면의 정산 의미는 수정하지 않았습니다.
- 최근 7/30/90일 잔액 추이는 기준점 전을 자료 부족으로 표시하고, 기준점 후 거래가 입력되지 않은 날짜에는 전일 잔액을 이어 표시합니다. 날짜별 수입·지출은 미기록을 0으로 단정하지 않습니다. 사냥과 보스·판매 수입을 분리하고 지출 분류를 표시합니다.
- 매월 지출 합계·건수·날짜별 목록과 수정/삭제를 제공합니다. 사냥 차액에 이미 포함된 지출은 연결 표시하고 잔액/지출 분석에서 다시 차감하지 않습니다.
- 목표에 현재 잔액·남은 금액·진행률·우선순위·활성/완료 상태를 표시하고, 최근 28일 가운데 14일 이상의 기록일이 있고 기록 순수익이 양수일 때만 추정 기간을 안내합니다. 완료 표시는 지출을 만들지 않습니다.

## 범위와 호환성

기존 스크린샷 인식 코드, 첫 칸 조각 판독, 다시 보지 않기, 사냥 캘린더, 보스 스케줄러/인원/클리어, 물욕템 원본, 비밀번호 기록장, API 키 보관, 방문자 표시, 제보 버튼, 검색 파일·사이트맵은 수정하지 않았습니다. 스타포스/잠재능력 가져오기, 채집, 강화 시뮬레이터, 캐시 뽑기, 경험치 분석을 신규 구현하지 않았습니다.

## 검토 후 보완

- 중복 선언된 타입과 임시 검증기를 공유 Zod 계약으로 통합했습니다. 중복 id·판매, 실제로 없는 날짜, 0메소 목표, 불일치 조정 차액을 거부합니다.
- 음수 사냥 차액을 지출·순수익에 반영하고 시작 잔액 설정 전에도 수입 통계를 표시합니다.
- 사냥 차액에 포함된 지출을 목록에서 누락하던 문제를 고쳐 수정·삭제할 수 있습니다.
- 기준일 이전부터 모든 날짜를 반복하던 차트 계산을 날짜별 증감 집계로 바꿨습니다. 7/30/90일 그래프와 정확한 금액 표를 제공합니다.
- 시작일에 새로 입력한 지출·판매는 생성 시각으로 판정합니다. 날짜만 저장된 기존 사냥·보스는 포함/제외 선택을 유지합니다.
- 저장 로직을 별도 Hook, DB 처리를 서버 모듈로 분리했습니다. 실패 시 입력값을 유지하고 동시 요청을 막습니다. 다른 탭에서 기록장이 바뀌면 bookId 검사로 잘못된 장부 저장을 거부합니다.
- 자산 JSON은 자산 조회 시에만 읽어 기존 사냥·보스 요청에 부담을 추가하지 않습니다.
- 판매액 수정/취소, 음수 잔액 조정, 목표 0원 방지, 모바일 입력칸 넘침을 보완했습니다.
- 목표 예상치는 미기록일을 임의 0수익으로 간주하지 않는 활동 횟수 기준입니다.

## 검증

- 자동 테스트 80개 통과: 계산, 계약, 기존 기록 보존 마이그레이션, 동시 저장·기록장 분리 및 기존 OCR 회귀 포함.
- TypeScript 및 수정 코드 ESLint 통과.
- 로컬 HTTP 통합 테스트 통과: 두 세션의 사냥·보스 저장 유지, 오래된 revision 거부, 로그아웃 분리.
- 실제 브라우저에서 시작 잔액 10억, 지출 1억, 잔액 9억, 목표 20억의 45% 진행률을 확인했습니다. 재접속 후에도 지출·목표가 유지됩니다.
- 운영 D1은 백업 후 추가 컬럼 두 개만 마이그레이션했습니다. 기존 사냥·보스 데이터와 OCR 구현은 유지했습니다.

강화비 자동 가져오기는 이번 범위에 포함하지 않습니다. 기록 기반 잔액이며 실제 게임의 보유 메소와 자동 동기화되지 않습니다.

## 운영 반영

2026-11-10 Cloudflare 배포 완료. `/income` 자산·지출 메뉴와 모바일 390px 화면을 확인했고 가로 넘침이 없습니다. 변경 파일 Prettier 및 최종 Cloudflare 빌드가 통과했습니다. 운영에 테스트 기록은 추가하지 않았습니다.

## 금액 입력 단위 안내

시작 잔액·실제 잔액·지출·목표 금액 입력칸 바로 위에 입력값을 만·억 단위로 실시간 표시합니다. 기존 정수 메소 입력과 저장 방식은 유지하며 빈 값과 숫자 외 입력도 안내합니다. 기존 `money` 유틸리티를 재사용합니다.
